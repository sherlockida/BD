## 1. 项目概述与 AI 协作规范

### 1.1 项目定位

AgentHub 是一个以 **IM 群聊为核心交互范式** 的多 Agent 协作平台。采用飞书风格 UI，PMO 智能编排，产物内联预览。

### 1.2 技术栈

| 层 | 技术 |
|----|------|
| 前端 | React 18 + TypeScript + Vite + Zustand + TailwindCSS + Monaco Editor |
| 后端 | Node.js + Express + WebSocket (ws) + TypeScript |
| 数据库 | PostgreSQL 16 + Drizzle ORM |
| 缓存 | Redis 7 |
| LLM | DeepSeek (dev) / Anthropic Claude + OpenAI GPT (prod) |
| 基础设施 | Docker Compose |

### 1.3 AI 协作流程

本项目采用 "Spec → Rules → Skills → TaskList → AB互检 → 复盘" 六阶段协作流程:

1. **Spec 先行**：任何功能先写 SPEC.md 明确验收标准
2. **Rules 约束**：RULES.md 注入所有 Agent 的 System Prompt
3. **Skills 沉淀**：每次协作结束沉淀可复用经验为 Skill
4. **TaskList 驱动**：Spec 拆成原子 Task，逐项完成标记
5. **AB 互检**：一个 Agent 写实现，另一个 Agent review
6. **复盘进化**：PMO 复盘 → 提取候选 Skill → 一键沉淀

### 1.4 关键约束

- 单文件 ≤ 300 行（React 组件）/ 500 行（Store/后端服务）
- MVP 保底：每个 Phase 结束必须有可演示版本
- 乐观更新 + 失败回滚：前端先响应，API 失败再通知
- 不在 master 直接推，使用 feature 分支

### 1.5 Commit 规范

```
feat: 新功能
fix: 修复
style: 样式
docs: 文档
refactor: 重构
chore: 杂项
```

## 2. 平台规格 SPEC

### 2.1 背景与目标

- **背景**：单 Agent 能力有边界，单聊体验无法承载"项目交付"级别的协作
- **P0 目标**：IM 风格群聊 + 2+ Agent 接入 + PMO 编排 + 产物内联预览
- **P1 目标**：版本时间线 + Diff 视图 + 回滚 + 一键部署
- **P2 目标**：多端同步、多人协作、Agent 市场计费

### 2.2 用户故事

1. **独立开发者**：1 人调度多个 Agent 完成"设计→编码→部署"全流程
2. **不懂代码的 PM**：自然语言描述需求 → Agent 自动产出可视化产物
3. **技术 Leader**：完整审计记录 + 版本历史 + Agent 行为约束治理

### 2.3 验收标准（v1.0 MVP）

- [x] 左栏对话列表：新建/搜索/归档/选择激活
- [x] 中栏聊天窗：流式消息渲染、Pin、引用、复制、重新生成
- [x] 单聊/群聊模式
- [x] PMO 拆任务 + Plan Card 可视化
- [x] 并行调度 + 失败降级
- [x] 4 个 Agent：Claude Code / Codex / OpenCode / 自建 DocAgent
- [x] 产物类型：code / webpage / doc，内联预览卡片
- [x] 部署卡 + 一键部署模拟
- [x] AI 协作三件套：SPEC.md / RULES.md / Skills/

### 2.4 核心接口契约

```ts
interface IAgent {
  meta: Agent;
  chat(input: AgentInput): AsyncIterable<AgentChunk>;
  healthCheck(): Promise<boolean>;
}

type AgentChunk =
  | { type: 'text'; delta: string }
  | { type: 'code'; language: string; code: string; filename?: string }
  | { type: 'artifact-draft'; artifactType, name, language?, content, commitMessage }
  | { type: 'tool-call'; tool: string; args: any }
  | { type: 'done' }
  | { type: 'error'; error: string };
```

## 3. AI 协作规则 RULES

本规则注入所有 Agent 的 System Prompt，同时约束人类开发者：

### R1 · 通信约定
- 优先输出最小可用产物，不"先讲方案再问一堆问题"
- 所有 Agent 回复以 AgentChunk 流式产出
- 不重复用户输入，不写多段免责声明

### R2 · 产物规范
- 完整作品用 `artifact-draft` chunk 输出
- commitMessage 遵循 git 规范：`<type>: <description>`

### R3 · 代码规范
- TypeScript 严格 typed，禁止 any（utilities 除外需注释）
- React 函数组件 + Hook
- 注释只写 WHY，不写 WHAT

### R4 · PMO 行为
- 先输出 Plan Card 再开工
- 优先匹配 capability tag 派单
- 最多一次 fallback，失败后 @ 用户求助
- 全部完成后输出"PMO 周报"

### R5 · 失败处理
- 重试策略集中在调度层，Agent 不自重试
- 产物写入 append-only，回滚也是新增版本

### R6 · 上下文管理
- 按时间顺序传递历史，超出上限做摘要
- Pinned 消息标记 `[PINNED]` 始终置前

### R7 · 安全信任
- Agent 不能直接执行 shell/写文件/调网络
- 一切动作先出 artifact-draft 让用户预览确认

### R8 · 沉淀经验
- PMO 主动提议沉淀 Skill
- 用户 hover Agent 消息 → ✨ 一键沉淀
- Skill 按 trigger 匹配自动召回

## 4. 开发规范

（综合自 `开发规范.md` 和 `CLAUDE.md` AI 协作规范部分）

### 4.1 人机分工铁律

| 维度 | 人 | AI (Claude Code) |
|------|-----|------------------|
| 需求拆解 & 优先级 | **全权负责** | 方案解读和 trade-off 分析 |
| 架构设计 | **全权负责** | 多方案对比，不改架构决策 |
| Bug 根因分析 | **主导** | 搜索、日志分析 |
| 代码编写 | 核心业务逻辑手写 | 样板代码、Mock、测试、适配器 |
| 代码审查 & 合并 | **最终决策** | 静态检查和建议 |
| 文档撰写 | 审查修改 | 初稿生成 |

### 4.2 Prompt 编写规范
- 一次一个问题，不塞多个不相关需求
- 精确到函数签名（名称/参数/返回值/失败行为）
- 附上下文代码片段，不让 AI 猜

### 4.3 可靠性规范
- 所有外部调用必须三项齐全：超时 (timeout) + 重试 (retry) + 兜底 (fallback)
- 所有 LLM 调用入口/出口打日志
- Fallback 设计：主路径 → 降级路径 → 优雅失败

### 4.4 会话管理
- 新功能/修 Bug/部署/代码审查各用独立会话
- 单会话 ≤ 10 轮
- 关键决策即时写入 dev-log

### 4.5 数据库编码规范
- 新建表设置 `LANG=C.UTF-8` + `--encoding=UTF-8 --locale=C.UTF-8`
- 连接池每个连接执行 `SET client_encoding = 'UTF8'`
- 中文乱码处理优先级：恢复 → 编码逆转 → 删除（最后手段）

## 6. 架构决策记录 ADR

### ADR-1：自研编排器
- **决策**：不使用 CrewAI/LangGraph/AutoGen
- **理由**：IM 交互范式需要定制调度（Plan Card 可视化、GenUI 暂停/恢复、用户中途干预），现有框架无法表达
- **代价**：需要自行实现 DAG 调度、容错、重试、Saga 补偿

### ADR-2：Planner 双路径
- **决策**：关键词快路径 (<100ms) + LLM 智路径 (~2s)
- **理由**：简单任务（如"写个 Hello World"）无需 LLM 规划开销；复杂任务（如"做电商网站"）需要 LLM 深度拆解

### ADR-3：Drizzle ORM
- **决策**：使用 Drizzle ORM 而非 Prisma
- **理由**：更轻量，SQL-like API，迁移可控

### ADR-4：Agent 适配器模式
- **决策**：IAgent 统一接口 + RemoteAgent(后端 API) / Mock(回退)
- **理由**：屏蔽厂商差异，Mock-First 策略让交互范式先跑通

### ADR-5：SSE + WebSocket 双通道
- **决策**：SSE 用于流式聊天（单向），WebSocket 用于实时事件（双向广播）
- **理由**：SSE 更简单可靠（HTTP 标准），WebSocket 补充实时推送

### ADR-6：乐观更新 + 失败回滚
- **决策**：前端先更新 Zustand，API 失败时回滚 + 系统消息
- **理由**：聊天场景对延迟敏感，不能等 API 返回才显示

### ADR-7：产物类型内容嗅探
- **决策**：looksLikeWebpage() 检测 HTML 标签/DOCTYPE，优先于 artifact.type
- **理由**：LLM 可能误标注产物类型，内容嗅探更准确

### ADR-8：预览 iframe 三层安全
- **决策**：CSP meta 标签 + AgentHub.util 运行时注入 + sandbox 属性
- **理由**：LLM 生成的 HTML 可能有语法错误/无限循环/恶意脚本

### ADR-9：Hydration 自愈
- **决策**：hydrateFromBackend() 发现 DB 为空时自动持久化本地 demo 数据
- **理由**：避免 FK 约束导致 artifact 保存失败

### ADR-10：DAG 容错调度
- **决策**：上游失败不阻塞下游，下游带 ⚠️ 警告继续
- **理由**：部分失败不应阻止整个编排流程

### ADR-11：GenUI 暂停/恢复
- **决策**：Agent 输出交互组件时任务 paused，等用户输入后恢复
- **理由**：解决"全自动 vs 全手动"的二元对立

### ADR-12：统一持久化门面
- **决策**：addMsg() 内部自动 apiPostMessage 到 DB
- **理由**：所有消息路径统一覆盖，避免遗漏持久化

### ADR-13：产物同轮去重
- **决策**：同一编排轮次内同名 artifact 用 Agent 后缀区分
- **理由**：避免版本 v6→v11 激增

### ADR-14：max_tokens=8192
- **决策**：DeepSeek 默认 4096 上调至 8192
- **理由**：HTML 长输出在 4096 下围栏闭合前截断

### ADR-15：后端全链路日志
- **决策**：server/src/utils/logger.ts 提供彩色结构化日志
- **理由**：请求→流式进度(每5s)→完整响应→耗时/字符统计→错误详情

### ADR-16：Dev 全部走 DeepSeek
- **决策**：开发环境统一 DeepSeek，生产按 vendor 分流
- **理由**：只有 DeepSeek Key，其他厂商预留

## 7. Skills 知识库

### Skill 1: Agent 适配器模式
- **触发**：接入 ≥ 2 个 LLM/Agent 厂商，API 有差异
- **做法**：IAgent 统一接口 → BaseAgent 公共逻辑 → 每个厂商一个 Adapter → Registry 集中管理
- **陷阱**：重试/限流/计费放 Registry/Scheduler 层，不放 Adapter

### Skill 2: 编排器任务规划
- **触发**：多 Agent 协作，模糊意图 → 子任务列表
- **做法**：Planner 输出 DAG → Scheduler 拓扑排序 + Promise.race → 失败降级在调度层 → Aggregator 写周报
- **陷阱**：用 Promise.race 而非 Promise.all；每个任务独立流式消息

### Skill 3: IM 流式消息
- **触发**：Agent 输出需 typing 效果
- **做法**：store 中 streaming 标记 + patchMsg 增量追加 + zustand 细粒度 selector + typing indicator + cursor 动画
- **陷阱**：stream 期间禁止重新生成（状态冲突）；不用整体 setState（雪崩 render）

### Skill 4: 产物版本控制
- **触发**：AI 产出需保留迭代历史
- **做法**：append-only 版本流 → upsert + 自动 Diff Card → 回滚 = 新增版本（不删除）
- **陷阱**：版本号用递增 int 而非 timestamp；多 Agent 并发写应 enqueue 串行

### Skill 5: 人机协作协议
- **触发**：人 + 多 Agent 要交付有规模的项目
- **做法**：Spec → Rules → Skills → TaskList → AB 互检 → 复盘
- **陷阱**：不跳过 Spec 直接 Code；Skill 必须带 When/How/Pitfalls 三段

## 8. 关键技术 Bug 修复记录

### 🐛 PostgreSQL 中文编码乱码
- **根因**：Docker 容器默认编码与中文不兼容
- **修复**：Docker Compose 设置 LANG + POSTGRES_INITDB_ARGS + 连接池 SET client_encoding
- **恢复优先级**：hex 检查 → 编码逆转 → 最后才删除

### 🐛 DAG 死锁
- **根因**：scheduler.ts dependsOn 只认 finished 不认 failed
- **修复**：检查改为 `d.every(d => finished.has(d) || failed.has(d))`

### 🐛 GenUI 暂停恢复缺失
- **根因**：调度器视 ChoiceCards 为普通 text chunk，不等待用户输入
- **修复**：识别 GenUI chunk → 任务 paused → 用户输入 → resume

### 🐛 Agent 上下文隔离
- **根因**：子 Agent 无法读取前置任务产物内容
- **修复**：Blackboard 共享 + buildContext 注入前置任务产出

### 🐛 HTML 产物预览白屏
- **根因**：iframe 中 JS 错误无捕获 + LLM 生成代码有语法错误
- **修复**：CSP meta + AgentHub.util 错误注入 + sandbox 属性

### 🐛 流式截断
- **根因**：max_tokens=4096 不够 HTML 完整输出
- **修复**：上调至 8192

### 🐛 产物未持久化
- **根因**：静默失败（FK 约束导致 save 失败但无错误提示）
- **修复**：Hydration 自愈 + DELETE API + 完整 CRUD
