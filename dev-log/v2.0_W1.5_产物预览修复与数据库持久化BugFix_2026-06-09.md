# v2.0 W1.5 — 产物预览修复与数据库持久化 BugFix

> 日期: 2026-06-09 | 类型: bug-fix + feat | 涉及: 前后端 14 文件

---

## 背景

用户反馈两个核心问题：
1. **产物无法落盘到数据库** — Agent 生成的内容刷新后丢失，历史/回滚/删除功能未真正持久化
2. **HTML 预览体验差** — 有时显示代码而非渲染页面、点击无功能按钮白屏、缺少刷新按钮

经代码审查 + 运行时调试确认根因后，实施了完整的修复方案（详见 `plan/bug_fix_V1.md`）。

---

## 根因分析

### 问题 1：产物未持久化

**表面现象**：`POST /api/artifacts` → 500，`POST /api/artifacts/:id/versions` → 404

**诊断过程**：
1. 后端 API 路由代码正确 ✅
2. Docker 容器运行正常 ✅
3. 数据库表结构存在 ✅
4. 手动 curl 测试 POST /api/artifacts → 201 ✅

**真根因**：前端 `hydrateFromBackend()` 发现 DB 无 conversation 时直接 return，保留了仅存在于内存的 demo 对话（及其 UUID）。后续 artifact 创建使用这些 UUID 作为外键 → PostgreSQL FK 约束失败 → 500。

```
前端启动 → hydrateFromBackend() → DB 无 conversation → 保留 demo 对话于内存
→ Agent 生成产物 → POST /api/artifacts { conversationId: "demo-UUID-不在DB中" }
→ PostgreSQL FK 约束失败 → 500
→ 产物不存在 → 后续 POST /versions → 404
```

同时发现 API 错误消息仅显示 HTTP 状态码（如 `Failed to create artifact: 500`），不显示后端返回的真实错误信息，增加了排查难度。

### 问题 2：HTML 预览缺陷

| 子问题 | 根因 |
|--------|------|
| HTML 显示为代码 | `PreviewBody` 仅按 `artifact.type` 判断渲染方式，`fenceExtractor` 兜底逻辑将所有未知语言映射为 `'code'` 类型 |
| 按钮点击白屏 | iframe `sandbox="allow-scripts"` 缺少 `allow-same-origin`，JS 操作 document 时抛 SecurityError 且未被捕获 |
| 无"功能未实现"提示 | Agent 生成的 HTML 无编码规范约束，无标准占位处理 |
| 无刷新按钮 | 预览区无任何工具栏 |

## 修复方案

### Phase 1: 数据库持久化

| 文件 | 改动 |
|------|------|
| `appStore.ts` `hydrateFromBackend()` | DB 为空时自动将本地 demo 对话持久化到 DB，回填已有 artifact |
| `appStore.ts` `handleChunkInto()` | 持久化调用改为 `.then().catch()` 模式，追踪 `_persistStatus`（saving → saved/error），失败时发送系统消息提示用户 |
| `appStore.ts` | 新增 `deleteArtifact()` 和 `deleteArtifactVersion()` action（乐观删除 + 失败回滚状态） |
| `api/client.ts` | 新增 `readError()` 从后端 JSON 响应提取真实错误消息；新增 `apiDeleteArtifact()` / `apiDeleteArtifactVersion()` |
| `types.ts` | `Artifact` 接口增加 `_persistStatus?: 'saved' \| 'saving' \| 'error' \| 'local-only'` |
| `server/routes/artifacts.ts` | 新增 `DELETE /:id` 和 `DELETE /:id/versions/:versionId` 路由（CASCADE 清理 + WS 广播 + latestVersionId 自动修复） |
| `server/ws/wsServer.ts` | `WSEvent` 类型新增 `artifact.deleted` 和 `artifact.version_deleted` |
| `server/index.ts` | `/api/health` 增加 schema 检查（验证 artifacts 表存在） |

### Phase 2: 预览修复

| 文件 | 改动 |
|------|------|
| `ArtifactPanel.tsx` `PreviewBody` | 完整重写：预览工具栏（刷新/源码切换/新标签页打开）、`looksLikeWebpage()` 内容嗅探、iframe sandbox 放宽为 `allow-scripts allow-same-origin` |
| `ArtifactPanel.tsx` `injectCsp()` | 注入 `AgentHub.util` 运行时：全局 `window.onerror` 防白屏 + `notImplemented()` Toast 浮层 + 无功能按钮自动拦截 |
| `ArtifactPanel.tsx` `HistoryBody` | 增加删除按钮（单版本 + 整个产物）、持久化状态指示器（⏳保存中 / ⚠️未保存）、latest 版本高亮 |
| `fenceExtractor.ts` `defaultNameFor()` | 扩展 HTML 检测：`xhtml`/`xml`/`svg` → `webpage` 类型 |
| `server/services/genuiCatalog.ts` | `CATALOG_SYSTEM_PROMPT` 追加编码规范：占位按钮规范、安全规范、错误处理、响应式设计 |

## 关键技术决策

1. **乐观更新 + 失败回滚** — 前端先更新 Zustand 状态获得即时响应，API 失败时回滚并通知用户
2. **持久化状态追踪** — `_persistStatus` 字段让 UI 可感知并展示每个 artifact 的同步状态
3. **预览安全三明治** — CSP meta 标签（外层）+ AgentHub.util 运行时（中层）+ sandbox 属性（内层），三层防护
4. **内容嗅探优先于类型声明** — `looksLikeWebpage()` 检测真实 HTML 内容，避免 artifact type 错误导致预览失败
5. **静默失败 → 显式通知** — API 错误从 `console.warn` 改为系统消息气泡，用户可见
