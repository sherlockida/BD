## 最终方案的三大支柱

### 支柱一：Canvas 主视图（"数字车间"隐喻）

把"飞书 IM 群聊"重塑为"数字车间"：
- Agent → 工位（Workstation）
- 用户需求 → 订单（Order）
- 产物 → 工件（Artifact Tile）
- PMO → 车间主任（Foreman）
- 派生关系 → 血脉连线（Lineage Edge）

技术栈选 `@xyflow/react`（原 React Flow，~50KB），节点 = React 组件可继承现有 Tailwind 飞书风格。

### 支柱二：生成式 UI（A2UI Catalog 协议）

- `AgentChunk` 新增 `ui-component` 类型
- v1 Catalog 收录 4 个组件：ChoiceCards / ColorPickerGrid / SliderRange / ConfirmCard
- Zod 强校验 + 不匹配降级为 text
- LLM 通过 ```` ```ui ... ``` ```` 围栏输出，后端 SSE 流解析下发
- 用户操作回传 → 后端注入 system message → Agent 自动续跑

### 支柱三：Demo 加分特效

- **Live Telemetry**：工位脉动条 + token/秒实时跳
- **PMO Replay**：5 分钟协作压缩为 15 秒动画回放
- **Skill Snap**：复盘后画布拓扑沉淀为 Skill 模板
- **Live Cursor Trails**（可选）：调度光带可见

## 反思

- **brainstorming skill 起效**：三个澄清问题精确定位了用户偏好（颠覆方向 / 杀手镜头 / 落地深度），避免了"做了一版用户不要"的浪费
- **调研给方案立住了根**：每条创新都能映射到 2026 行业前沿，答辩时不会被"你这是拍脑袋"
- **零侵入原则可继承**：v1.1 的 90% 工程资产复用，意味着即使 PoC 失败也不会丢现有作品
- **风险敞口已识别**：LLM 不主动出 GenUI、@xyflow 节点性能、Canvas 学习成本——都给了对策

> 本设计的核心不是"加更多功能"，而是"换一个评委从未见过的视觉范式"。
> 答辩时第一帧就让评委看到"3 个 Agent 工位同时跳动 + 工件沿连线长出"——这个画面，市面 Demo 里都没有。
