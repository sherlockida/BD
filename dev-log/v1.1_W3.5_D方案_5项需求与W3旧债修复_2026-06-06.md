## W3 旧债修复

### Debt 1: messages 游标分页失效
- 旧代码 `and()` 内只有 `eq(conversationId)` 一项条件，gt 是注释占位
- 试 1: `gt(messages.createdAt, cursorTs)` Drizzle helper — 无效
- 试 2: `sql\`${col} > ${cursorTs.toISOString()}::timestamptz\`` — 失败原因: **JS Date.toISOString() 截断到毫秒，PG 存的是微秒（.107875 → .107），cursor msg 自身被错误纳入结果**
- 试 3: `sql\`... AND created_at > (SELECT created_at FROM messages WHERE id = ${cursor}::uuid LIMIT 1)\`` — ✅ 子查询，**完全在 SQL 内做精度比较，绕过 JS 浮点损失**
- E2E 验证: cursor=msg1 → 1条，cursor=msg2 → 0条，no cursor → 2条

### Debt 2: GET /api/artifacts 列表缺失
- 加 `artifactsRouter.get('/', ...)`，支持 `?conversationId=` 过滤
- E2E 验证: 创建 1 个 artifact 后 list 返回 1 条

### Debt 3: broadcastToConversation 写了从没人调
- messages.ts: POST /messages 后广播 `message.new`
- artifacts.ts: POST / 后广播 `artifact.new_version`
- artifacts.ts: POST /:id/versions 后广播 `artifact.new_version`

### 副带修复
- artifacts FK 顺序: 旧代码先插 version 再插 artifact，违反 FK；改为先插 artifact 再插 version
- skills.ts: 接受 clientId

- messages.ts: 接受 clientId

## ID 一致性方案

发现：前端 `uid('conv')` 生成 timestamp+random，PG schema 用 `uuid` 列，二者不兼容。

方案：
1. 加 `genUuid()` 用 `crypto.randomUUID()` 生成 RFC 4122 v4 UUID
2. 服务端 POST 接受可选 `id` 字段，存在则用，否则生成
3. 前端创建持久化对象时一律 `genUuid()`，发给后端时附带 id
4. 前后端 ID 永远一致 → 无需 swap → 无 race condition
