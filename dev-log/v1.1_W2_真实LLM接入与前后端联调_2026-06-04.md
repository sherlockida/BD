## 修改背景

v1.1 W2 目标：从 Mock Agent 升级为真实 LLM API 调用，Planner 从关键词匹配升级为 LLM 驱动。

用户有 DeepSeek API Key（无 Anthropic/OpenAI Key），所以 DeepSeek 是当前唯一的真实 LLM 提供商。

## 修改内容

### 1. LLM Gateway 服务 (server/src/services/llmGateway.ts)
- **三厂商统一接口**：Anthropic SDK（Claude）、OpenAI SDK（GPT/Codex）、OpenAI 兼容 SDK（DeepSeek）
- **Vendor → Provider 映射**：
  - `claude-code` → anthropic | `codex` → openai | `open-code` → deepseek | `custom`/`orchestrator` → deepseek
- **智能降级**：主 provider 不可用时自动切到可用 provider
- **两个模式**：
  - `chatWithAgent()`：流式 SSE（AsyncIterable<AgentChunk>）
  - `chatWithAgentSync()`：同步返回（给 Planner/Aggregator 用）

### 2. LLM Planner 服务 (server/src/services/plannerService.ts)
- **三路径策略**：
  1. Fast path：关键词正则匹配（4 种模式，<100ms）
  2. Smart path：LLM 生成 JSON 约束 DAG（~2s）
  3. Fallback：单 Agent 直派
- **JSON Schema Prompt**：告诉 LLM 可用 Agent 列表，约束输出格式
- **DAG 生成**：LLM 自动决定并行/串行关系

### 3. Agents 路由升级 (server/src/routes/agents.ts)
- `POST /api/agents/chat`：Mock → 真实 LLM SSE 流式
- `POST /api/agents/plan`：新增，LLM 驱动规划
- `GET /api/agents/providers`：新增，查询可用 LLM 提供商
- AgentMeta 添加 `systemPrompt` 字段，每个 Agent 有专属人设

### 4. 前端 API 客户端 (agenthub-mvp/src/api/)
- `client.ts`：REST API 封装 + SSE 流式消费（ReadableStream → AgentChunk）
- `wsClient.ts`：WebSocket 房间订阅/事件分发，断线自动重连
- `remoteAgent.ts`：实现 IAgent 接口，调用后端 SSE 替代 Mock

### 5. 前端集成
- `registry.ts`：主流 Agent 改用 RemoteAgent，保留 Mock 引用
- `vite.config.ts`：新增 `/api` → `localhost:3001` 代理 + `/ws` WebSocket 代理

## 关键决策

### 决策 1: 智能降级 vs 报错
选择智能降级：主 provider 不可用时自动切到可用 provider，而非直接报错。
用户只有 DeepSeek Key，所有 Agent 都走 DeepSeek，体验不受影响。

### 决策 2: LLM Planner 保留关键词路径
关键词 fast path 覆盖 80% 常见场景，延迟 < 100ms。
LLM smart path 处理新意图，延迟 ~2s。
两者互补，不是替代关系。

### 决策 3: 前端 API 客户端使用 SSE，非 WebSocket
Agent 聊天流式响应用 SSE（单向流），WebSocket 用于实时事件推送（typing、状态更新、部署进度）。
SSE 更适合 Agent→Client 的单向文本流，实现更简单。

### 决策 4: Vite 代理而非 CORS
前端开发用 Vite proxy（`/api` → `localhost:3001`），避免 CORS 配置和跨域 Cookie 问题。
生产环境用 Nginx 反代。
