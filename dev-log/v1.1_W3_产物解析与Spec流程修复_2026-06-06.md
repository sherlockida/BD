## 二、根因分析

### 2.1 T4/T5/T6 — 没人把 LLM 输出里的代码块抽成 Artifact

**调用链路（旧）**：
```
DeepSeek SSE
  → server/src/services/llmGateway.ts:chatWithDeepSeek      仅 yield { type:'text', delta }
  → server/src/routes/agents.ts:POST /api/agents/chat       透传
  → agenthub-mvp/src/api/client.ts:streamAgentChat          解析 SSE
  → agenthub-mvp/src/agents/remoteAgent.ts:chat             把 text chunk 直接 yield
  → agenthub-mvp/src/store/appStore.ts:handleChunkInto      只把 text 累加到聊天气泡
```

**关键缺口**：上面这条链路从头到尾没有任何地方解析 markdown 代码围栏。LLM 实际回复里
```html
<!DOCTYPE html>...
```
的内容全部当成普通聊天文字渲染，没人调 `upsertArtifact()`。`appStore.handleChunkInto`
**已经**为 `artifact-draft` chunk 实现了"创建/更新 artifact + 发 artifact card + 发 diff card"
（appStore.ts:850-933），但没有上游会发这种 chunk。

这一空缺其实在《开发规范.md》第八节 "W3 行动项汇总" 第 3 条已明确列出：
> **产物解析**：从 LLM 流式输出中自动提取 artifact-draft chunk

### 2.2 T12 — 两个独立的 bug 叠加

#### Bug 2.2.a — backend `AGENT_METAS` 缺少 `agent_doc`

- 前端 `agents/registry.ts:57-68` 注册了 `agent_doc` (DocAgent)。
- 后端 `server/src/routes/agents.ts:22-67` 的 `AGENT_METAS` 只有 PMO / claude_code / codex / open_code。
- Planner 场景 D（命中 `spec` 关键词）固定派 `agent_doc`，但 `fallbackAgentId` 未设。
- 前端 `RemoteAgent.chat` → `POST /api/agents/chat { agentId: 'agent_doc' }` → 后端 line 119-122 返回 404 `Agent not found: agent_doc`。
- 调度器 `tryRun` 捕获错误 → 无 fallback → `events.onTaskDone(task, false, '执行失败')` → 群里"撰写文档"任务红字失败。

#### Bug 2.2.b — `BubbleBody` blockquote 渲染没给 children 加 key

- `MessageBubble.tsx:219` 原代码：
  ```jsx
  out.push(<blockquote key={out.length}>{buf.map(inline)}</blockquote>);
  ```
- `inline(text)` 返回的是 `<>{parts}</>`（Fragment），多个 Fragment 在同一数组里 React 必须 key。
- /spec 模板里有一行 `> 请补全后回复"确认 Spec"...`，blockquote 触发该路径。第二行触发警告，第一行也算作列表项。

## 三、修复方案

### 3.1 新增前端流式围栏解析器（修 T4/T5/T6）

**新文件**：`agenthub-mvp/src/agents/fenceExtractor.ts`

设计要点：
- `createFenceExtractor()` → 返回 `{ feed(delta), flush() }` 的小型状态机。
- 状态机：`outside` ↔ `inside`，每次 `feed` 返回应发的 `AgentChunk[]`。
- **跨 delta 边界识别**：保留 `SAFE_TRAILING=3` 字节尾缓冲，避免 ` ``` ` 被切到下一 delta 后认不出来。
- **lang token 行内拼接**：进入 inside 前必须见到换行，否则 pending 留住等待下一 delta。
- **稳定命名**：`defaultNameFor(lang)` 把语言映射成统一文件名（`index.html` / `style.css` / `script.tsx` ...），同语言多块按 `name-2.ext` 自增。
- **同名 = 新版本**：第二轮生成产生同名 `index.html` → `appStore.upsertArtifact` 已有逻辑会创建 v2 并自动发 DiffCard。**这是 T5 能成立的关键前提**。

**接入**：`agenthub-mvp/src/agents/remoteAgent.ts`
- 收到后端 `text` chunk → 喂给 `extractor.feed()` → 把返回的 `text` / `artifact-draft` 直接 yield 给上游。
- `done` / `error` / 异常路径都调 `extractor.flush()`，避免吞内容。
- 后端已显式给出 `code` / `artifact-draft` 的旧路径仍透传，保持向后兼容。

### 3.2 UX：第一个产物到达时自动打开右侧面板

`agenthub-mvp/src/store/appStore.ts:handleChunkInto` 在 artifact card 之后追加：
```ts
set(s => ({ ...s, activeArtifactId: artifact.id, artifactPanelOpen: true }));
```
理由：用户做 T4 第一步时，需要主动点"产物 (N)"按钮才能看到面板。第一次产出自动打开能让 T4/T5/T6 路径"开箱即看"。后续切换 artifact 不会被覆盖（已存在的会变成更新而不是新建）。

### 3.3 后端补注册 `agent_doc`（修 T12 - 404）

`server/src/routes/agents.ts:AGENT_METAS` 末尾追加 `agent_doc` 条目，systemPrompt 与前端 registry 保持一致。

### 3.4 Planner 增加防御性 fallback（修 T12 - 韧性）

`agenthub-mvp/src/orchestrator/planner.ts` 场景 D：
- 正则增加 `确认\s*spec`，让用户直接发"确认 Spec"也能命中（之前是靠 `spec` 关键词被动匹配）。
- 给 "撰写文档" 任务设 `fallbackAgentId: 'agent_open_code'`。万一 DocAgent 在后端历史版本里没注册，自动降级到 OpenCode 完成，群里不再"红字失败"。

### 3.5 React key 警告修复（修 T12 - warning）

`agenthub-mvp/src/components/MessageBubble.tsx:219`
- 旧：`{buf.map(inline)}` — Fragment 无 key
- 新：`{buf.map((b, k) => <span key={k}>{inline(b, k)}{k < buf.length - 1 ? <br /> : null}</span>)}` —
  - 显式 span 带 key
  - 多行 blockquote 之间补 `<br />` 保留视觉换行

## 六、回答《开发规范》§2.3 三问

针对新增的 `fenceExtractor.ts`：

1. **调用链路**：
   - **上游**：`remoteAgent.chat()` 在收到后端 SSE `text` chunk 时调 `feed(delta)`；流结束（`done`/`error`/异常）调 `flush()`。
   - **下游**：`feed/flush` 返回的 `AgentChunk[]` 被 yield 到 orchestrator/store；`artifact-draft` 会触发 `handleChunkInto` 里既有的 artifact 创建/版本累加/DiffCard 发送逻辑。

2. **失败后果**：
   - 解析器自身不抛异常（无 try/catch 必要，全是字符串操作）。
   - 若 LLM 流意外中断，flush() 仍会把已收到的代码内容当 "（流意外结束）" 版本 emit，不丢用户已经看见的产物。
   - 若 LLM 完全不出围栏（纯文字），表现等同旧行为：所有内容当 text 滚到聊天气泡。

3. **数据流向**：
   - 输入：来自 SSE `data: {"type":"text","delta":"..."}` 解出的 delta 字符串。
   - 输出：仅生成 `{ type:'text', delta }` 与 `{ type:'artifact-draft', artifactType, name, language, content, commitMessage }`。
   - 落地：text → MessageBubble 渲染；artifact-draft → `appStore.artifacts` + 群里 artifact card + 右侧产物面板（v1，或同名增量 v2/v3 + DiffCard）。

## 七、回归风险与后续

### 已规避的回归
- `code` / `artifact-draft` 旧 chunk 路径保留透传，不破坏未来 backend 直接发结构化 chunk 的方案。
- text-only 路径（agent 不写代码时）零行为变化。
- 自动开面板只在产物到达时触发，不抢用户已展开/收起的状态后续操作。

### 已知小限制
- 无 lang 的 ` ``` ` 块统一映射 `snippet.txt` / doc。若多用户同时让 agent 写无语言代码，会编号自增 `snippet-2.txt`。
- 默认文件名固定，多个 HTML 项目共存时所有 v 都堆在同一 `index.html` 下。可在未来加 conversationId 维度的命名（足够 MVP 用，先不做）。

### 后续可选优化
1. agent 自己在围栏外说明文件名（如 "我创建了 `landing-page.html`：" + ```html` ...```），可改 fenceExtractor 解析这种 hint 取代默认命名。
2. 把 `fenceExtractor.test.ts` 接到 vitest，纳入 CI gate。
3. 把"自动打开面板"做成可关闭偏好（用户可能反感）。
