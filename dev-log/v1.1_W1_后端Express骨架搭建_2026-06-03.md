## 关键决策

### 决策 1: Drizzle ORM 选型确认
- **理由**: 比 Prisma 更轻量，SQL-like API，TypeScript 类型推断更好
- **风险**: 生态不如 Prisma 成熟，但 AgentHub 的数据模型不算复杂

### 决策 2: WebSocket 房间模型
- 一个 WebSocket 连接可订阅多个 conversation
- 使用 `subscribe`/`unsubscribe` 客户端消息协议
- 路由层通过 `broadcastToConversation()` 推送实时事件
- **优势**: 解耦了 HTTP 路由和 WS 推送，路由不需要知道 WS 连接细节

### 决策 3: 在内存 Agent 注册表
- 当前 Agent meta 数据存内存（与 MVP 一致）
- v1.1 W2 将 API keys 绑定到 users 表的 api_keys JSONB 字段
- Agent 市场(v1.2)时再建独立的 agent_templates 表

### 决策 4: 渐进式数据迁移
- W1: 后端 REST API 可独立 CRUD，前端仍用 Zustand（不连后端）
- W1→W2 过渡: 前端添加 TanStack Query 层，逐步替换 Zustand 中的 Mock 数据
- MVP 纯前端版本始终可独立运行（回退保障）

### 决策 5: Rate Limiter 先用内存实现
- W1 用 `Map<string, Bucket>` 内存存储
- W2 迁移到 Redis (ioredis + token bucket Lua script)
- 内存实现满足开发阶段的限流需求
