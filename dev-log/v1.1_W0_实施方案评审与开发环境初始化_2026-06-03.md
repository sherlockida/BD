## 修改背景

进入 v1.1 开发前，对 AgentHub_Imp.md 完整落地方案进行评审。需要回答三个核心问题：
1. 是否需要引入现有多 Agent 框架（CrewAI/LangGraph/AutoGen）
2. 分阶段实现计划的具体重点是什么
3. 建立 AI 协作开发记录的自动归档机制

## 关键决策

### 决策 1: 自研编排引擎，不绑定第三方框架
- **选项 A**: 引入 CrewAI / LangGraph / AutoGen
- **选项 B**: 自研 PMO 编排器
- **选择**: B
- **理由**: AgentHub 的 IM 群聊交互范式（用户可随时 @ 插话干预、Agent 产出按时间线自然交错）与现有框架的 pipeline/DAG 严格执行模式存在根本差异。适配框架的扭曲成本 > 自研成本。但借鉴 LLMCompiler 的 JSON Schema 约束 DAG、LangGraph 的显式状态机概念。
- **风险**: 自研调度器需自行处理超时/重试/取消，v1.1 的 Scheduler 增强已覆盖这些需求。

### 决策 2: Planner 双路径渐进策略
- 保留 MVP 的关键词匹配作为 fast path（延迟 <100ms，覆盖 80% 场景）
- 新增 LLM 驱动作为 smart path（延迟 ~2s，处理未见过的复杂意图）
- Router 自动选择：先关键词匹配，不命中走 LLM
- **理由**: 避免过度依赖 LLM 导致响应变慢，同时保证复杂意图也能被正确处理。

### 决策 3: Dev-log 命名规范
- 格式: `{版本号}_{第几阶段}_{修改内容简述}_{日期}.md`
- 阶段使用方案中的 W1/W2/W3/W4 对齐
- 每次代码修改后自动凝练写入
