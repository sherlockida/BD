# v2.1 W1 — Orchestrator 2.0 智能多Agent编排器实现

> **日期**: 2026-06-09 | **状态**: ✅ 完成 | **基于**: plan/Orchestrator_update_Imp.md

---

## 交付概要

按照 5 个阶段的方案，完成了智能多 Agent 编排器的全面升级。共新增 11 个模块文件、修改 7 个现有文件、编写 133 个测试用例（全部通过）。

## 新增文件

### Phase 1: 基础设施
- **server/src/db/schema.ts** (修改) — 新增 `orchestrator_plans` 和 `execution_traces` 两张表，支持计划持久化和执行追踪
- **server/src/services/plannerService.ts** (重写) — 统一规划器：Zod 校验 + LLM 依赖映射修复 + 计划持久化 + Checkpoint 恢复
- **agenthub-mvp/src/types.ts** (扩展) — 新增 30+ 类型：Blackboard、Critic、Saga、Trace、IntentClassification 等

### Phase 2: 智能规划
- **classifier.ts** — 3 阶段意图分类（关键词 → 规则评分 → LLM 语义理解），解决"做网站"vs"检查网站"的语义歧义
- **agentSelector.ts** — 多因子 Agent 选择（能力匹配 35% + 专业化 10% + 负载 20% + 成功率 20% + 新近度 10% + 多样性 5%）
- **supervisor.ts** — LLM 驱动编排主管：动态规划、Agent 分配、进度监控、动态重规划、超时管理、上下文注入

### Phase 3: 协作通信
- **blackboard.ts** — bMAS 黑板架构：公共区（facts/decisions/artifacts/constraints/progress）+ 私有区（drafts/concerns/proposedChanges），支持序列化持久化

### Phase 4: 质量保证
- **criticAgent.ts** — 质量评审 Agent：4 维度评分（完整性/代码质量/安全性/可用性），4 种评审策略（多数投票/共识/LLM-as-Judge/人工确认）
- **pmoSynthesizer.ts** — PMO 合成器：结果合并、冲突检测、结构化报告生成（Markdown + 简要摘要）

### Phase 5: 可观测性
- **trace.ts** — 执行追踪：结构化日志（步骤/阶段/输入输出/耗时/元数据），支持按计划和任务查询
- **stallDetector.ts** — 停滞检测：Token 产出速率监控 + 静默轮次计数 + 自动标记
- **saga.ts** — Saga 事务补偿：注册可补偿操作 → 失败时反向执行补偿链
- **PlanCard.tsx** (升级) — 进度可视化：阶段指示器、进度条、复杂度徽章、评审分数、重试计数、停滞警告
- **BlackboardCard.tsx** — 黑板 UI：事实卡片、决策记录、产物列表、约束条件、进度条、私有空间

## 修改文件
- **orchestrator/index.ts** — 统一导出 2.0 所有模块，保留旧 API 兼容
- **orchestrator/scheduler.ts** — 重写：超时机制（120s/任务、600s/计划）、指数退避重试、停滞检测集成、黑板集成、产物绑定、追踪记录
- **orchestrator/aggregator.ts** — 标记 deprecated，委托到 PMO Synthesizer
- **orchestrator/planner.ts** — 添加 @deprecated 标记和迁移指南
- **components/PlanCard.tsx** — 升级：阶段指示器、进度条、复杂度徽章、评审分数、重试计数、停滞警告
- **components/BlackboardCard.tsx** — 新建黑板可视化组件
